# Fedora 45 research — what the rebase changes, checked against primary sources

Status: research written 2026-10-20, the day after F45's second-try GA target
passed its Go/No-Go window. Companion to notes/fedora-45-rebase.md (the
beta-era pass, 2026-09-18/19); this file re-checks the flag the owner raised
("f45 dropping fbcon"), the kernel, the fedora-bootc :45 image, rpm-ostree,
and the dates, against the change proposals, dist-git, koji, quay, and the
mailing-list archive. Labels: CONFIRMED = verified from a primary source
(artifact, config, archive) on 2026-10-20 unless noted; REPORTED = secondary
source; BETA-STAGE = verified against F45 Beta, can still move by GA;
UNVERIFIED/UNKNOWN = no source found.

## Verdict

The owner's flag is a real change wearing the wrong name. Fedora 45 does not
drop fbcon from the kernel — the f45 dist-git kernel config is byte-identical
to f44's (0 diff lines; `CONFIG_FRAMEBUFFER_CONSOLE=y`, `CONFIG_VT=y`,
`CONFIG_DRM_VGEM=m` all stand) — it replaces fbcon as the *default VT
console in userspace* with kmscon, repointing `autovt@.service` to
`kmsconvt@.service` (https://fedoraproject.org/wiki/Changes/UseKmsconVTConsole,
shipped in Beta). That change has no teeth for this repo: the boot path
(grub → kernel → plymouth, `rhgb quiet`), the serial console the VM smoke
reads, and greetd's DRM sessions are all outside its blast radius, and the
revert is "remove kmscon from the manifest". The kernel is 7.2.x in both F44
and F45 — not a delta. The rebase's one confirmed code break remains the PAM
stack move out of `/etc/pam.d` (notes/fedora-45-rebase.md §1), and the new
fact since the beta pass is a good one: rpm-ostree 2026.3 explicitly added
support for F45's relocated repository configs and GPG keys, which is what
this repo's rpm-ostree compose walks into. GA has slipped: Final was declared
NO-GO on 2026-10-15, target moved to Oct 27, contingency Nov 3.

## 1. fbcon: the flagged claim, chased down

- The change: "Use kmscon as default VT console" —
  https://fedoraproject.org/wiki/Changes/UseKmsconVTConsole (owner Jocelyn
  Falempe, Red Hat; FESCo #3513 https://pagure.io/fesco/issue/3513;
  announcement
  https://lists.fedoraproject.org/archives/list/devel-announce@lists.fedoraproject.org/message/MBGFWEQXZP3NFMDB5446ZD6ALUZCUNNI/;
  status "100% code completed" in the F45 Change Set,
  https://fedoraproject.org/wiki/Releases/45/ChangeSet). CONFIRMED as an
  accepted F45 change, shipped in the Beta (verified at beta in
  notes/fedora-45-rebase.md §6: kmscon-10.0.3-2.fc45 installed by default).
- What it actually does: installs kmscon by default and repoints the
  `/usr/lib/systemd/system/autovt@.service` symlink to `kmsconvt@.service`,
  so switching to a VT runs a userspace terminal (which itself runs agetty)
  instead of the kernel's fbcon emulator. The package is split
  (kmscon / kmscon-gl) so servers don't pull EGL. Source: the change page's
  Scope section. CONFIRMED.
- What it explicitly does NOT do: "fbcon will still be compiled in the
  kernel", "This change won't affect the installation, the boot process
  (like encryption password fallback)", and "If kmscon fails to launch, it
  will fallback to getty/fbcon" (change page, Detailed Description). The
  long-term goal — "deprecate fbcon/fbdev emulation in the kernel" — is
  stated as a direction, not done in F45. CONFIRMED.
- Kernel-config ground truth, checked directly: fetched
  https://src.fedoraproject.org/rpms/kernel/raw/f45/f/kernel-x86_64-fedora.config
  and the f44 twin (2026-10-20); the two files are byte-identical — zero
  diff lines. Both carry `CONFIG_FB=y`, `CONFIG_FRAMEBUFFER_CONSOLE=y`,
  `CONFIG_VT=y`, `CONFIG_VGA_CONSOLE=y`, `CONFIG_DRM_FBDEV_EMULATION=y`,
  `CONFIG_DRM_SIMPLEDRM=y`, `CONFIG_DRM_PANIC=y`. So: no kernel-config
  drop of fbcon, fbdev, or the VT layer in the F45 branch; tty1–63 and the
  getty machinery are untouched; simpledrm handling unchanged. CONFIRMED
  (as of the branched f45 config; a post-GA rebuild could theoretically
  differ — cheap to re-check the same URL after GA).
- What changes on tty1–63: the terminal emulator behind the getty. Tools
  that configure the kernel console break under kmscon (`setfont`,
  `loadkeys`, `gpm`), and starting a graphical app from the VT needs
  `kmscon-launch-gui` because a DRM session holds master exclusively
  (change page, Documentation section). Irrelevant to this repo — sessions
  are started by greetd, never from a VT.
- Impact, this repo:
  - plymouth + `rhgb quiet`: plymouth runs on DRM and the change page says
    the boot process is unaffected; the handoff grub → kernel → plymouth
    is a kernel-console and DRM path, not a userspace-VT one. CONFIRMED by
    the change text; BETA-STAGE in the sense that the final compose's
    plymouth+kmscon combination hasn't been booted by us yet.
  - VM smoke (console over ttyS0, greps kernel output for wake/resume):
    untouched. `console=ttyS0` is a kernel console selection; kmscon
    claims VTs on seat0, never the serial console, and the kernel's own
    console output — the thing the smoke greps — exists independently of
    which userspace terminal renders tty0. CONFIRMED structurally; the
    live-ISO serial boot test in the rebase notes' test plan (§ test 6)
    is the check.
  - Installer/ISO boot experience: no change expected — fbcon stays in the
    kernel, plymouth unaffected, and the Anaconda changes in F45 (WebUI for
    Atomic ISOs, Stratis) happen upstream of this repo's own BIB-built ISO
    (notes/fedora-45-rebase.md §8).
  - Known kmscon regressions from the change thread, all pre-beta testing
    on F43: an SELinux AVC on netlink_kobject_uevent causing a 100%-CPU
    spin (policy fix identified), nvidia-open quirks, font resize glitches
    (https://discussion.fedoraproject.org/t/172602). REPORTED (change
    thread), not re-verified against the shipped F45 build.

## 2. Kernel

- Version: F45 ships kernel 7.2.x. koji has fc45 builds of 7.2.10 and
  7.2.11 (https://kojipkgs.fedoraproject.org/packages/kernel/7.2.11/ — the
  `300.fc45/` entry; CONFIRMED 2026-10-20); 7.3.0 exists only as
  0.rc*/fc46 and eln159 builds (rawhide —
  https://kojipkgs.fedoraproject.org/packages/kernel/7.3.0/). F44 also
  ships 7.2.x (notes/fedora-45-rebase.md: "F44 already ships 7.2"). So the
  rebase does not move the kernel series — a quiet rebase on this axis.
  Expect 7.2.11-or-later at GA; the exact GA build is BETA-STAGE/UNKNOWN
  until the final compose lands.
- DRM/vgem/virtio-gpu, from the f45 branch config (URL in §1): CONFIRMED —
  `CONFIG_DRM_VGEM=m` (vgem still built, still lands in modules-extra —
  the October smoke bite was the GitHub runner's Azure kernel
  6.17.0-1022-azure dropping vgem from its modules-extra, a runner-image
  fact with no Fedora counterpart; the kvm action's out-of-tree vgem build
  stays the answer on runners, and a Fedora 45 guest keeps shipping vgem),
  `CONFIG_DRM_VIRTIO_GPU=m` with `CONFIG_DRM_VIRTIO_GPU_KMS=y` (the smoke
  VM's display path, unchanged), `CONFIG_DRM_SIMPLEDRM=y`.
- `CONFIG_DRM_PANIC=y` with `DRM_PANIC_SCREEN="qr_code"` and
  `DRM_PANIC_SCREEN_QR_CODE_URL="https://drm-panic.fedoraproject.org#"` —
  present in both f44 and f45 (identical configs). The F45 "DRM Panic
  Frontend" change (https://fedoraproject.org/wiki/Changes/DrmPanicFrontend)
  is the web frontend for the qr-code panic screen, not a kernel change.
  A kernel panic on a 45 appliance shows a QR code on the DRM device
  instead of a boot console dump — cosmetic for the smoke (which reads
  serial), worth knowing when reading a dead guest's screen.
- modules-extra moves: none found. The f45 config diff being empty is the
  whole story on the config side; no package-level modules-extra split was
  announced in the Change Set. UNVERIFIED beyond the config (the package
  lists themselves weren't enumerated).

## 3. The fedora-bootc :45 image

- The tag exists and is live: quay.io/fedora/fedora-bootc `:45` last
  modified 2026-10-19T15:28Z, manifest list
  `sha256:4776d2e96e263938a1b54c5c3a4cdd1c2ca723207b063a58ef36e1eda2fc9d61`
  (4 arch children; quay API, CONFIRMED 2026-10-20). Record the digest at
  rebase time; the tag floats daily.
- Source of truth moved: the image is built from
  https://gitlab.com/fedora/bootc/base-images (github.com/fedora-cloud/fedora-bootc
  is gone — GitHub API returns Not Found; CONFIRMED). `fedora-45.yaml` is a
  thin treefile (`releasever: 45`, repo `fedora-devel`, includes
  fedora-bootc.yaml → fedora-standard.yaml); commits show
  "Update Fedora 45 REPOS_IMAGE to Fedora-45-20261019.n.0" — the :45 image
  is composed daily from the F45 composes. The `fedora.repo` in that repo
  uses `baseurl=` against the Everything repos with keys from
  `distribution-gpg-keys` (CONFIRMED from the raw files).
- What actually changes inside the image: the big one is the repo
  relocation (§7) — F45's `fedora-repos` ships repo definitions under
  `/usr/share/dnf5/repos.d` and keys under `/usr/share/pki/rpm-gpg`
  instead of `/etc/yum.repos.d` and `/etc/pki/rpm-gpm` (change:
  https://fedoraproject.org/wiki/Changes/RelocateRpmRepoConfigsToUsr —
  CONFIRMED from the change page). rpm-ostree 2026.3 added explicit
  support "for Fedora 45's relocated repository definitions and RPM GPG
  keys while retaining compatibility with older layouts" (#5624,
  https://github.com/coreos/rpm-ostree/releases/tag/v2026.3). Anything in
  kuma that globs or asserts `/etc/yum.repos.d` inside the base image is
  reading an empty directory from now on.
- bootc version in the image: 1.16.9 at Beta (notes/fedora-45-rebase.md §9,
  verified by RPM inspection at beta) — same minor as F44's 1.16.10, no
  delta. BETA-STAGE.
- systemd version in the image: UNVERIFIED — not checked against the image
  or the F45 repo for this file; nothing in the Change Set announces a
  systemd behavior change relevant to the units kuma writes.
- os-release handling: no change found. `/etc/os-release` has been a
  symlink to `/usr/lib/os-release` for many releases and nothing in the
  Change Set or the base-images repo moves it; kuma's `--pull=never`
  os-release probe keeps working. CONFIRMED as "no change found" (negative
  result — the probe test in the rebase plan is the real check).

## 4. rpm-ostree

- v2026.3, released 2026-09-10
  (https://github.com/coreos/rpm-ostree/releases/tag/v2026.3). CONFIRMED
  from the release notes:
  - Two Moderate security fixes (GHSA-2m78-7qj3-jmvc treefile-modifier
    polkit bypass; GHSA-rq45-x7mc-f7h8 transaction-socket resource
    exhaustion). The build environment's rpm-ostree should be ≥ 2026.3
    regardless of the rebase.
  - "#5624 Support relocated repo configs and GPG keys (Fedora 45+)" —
    the compose path knows about F45's `/usr/share/dnf5/repos.d` layout.
    This is the item that makes the rebase compose-able; an older
    rpm-ostree facing a :45 seed is the failure mode to avoid.
  - "#5620 composepost: Add subs_dist equivalency for /var/lib/selinux" —
    fixes SELinux AVCs through the /var/lib/selinux compatibility symlink.
  - ostree-ext bumped to the revision bootc 1.16.11 uses.
- No treefile-format or compose-API breaking change in the release notes.
  The repo's own-base compose (treefile + rpm-ostree building blocks) has
  no announced behavior change beyond the repo-layout support. CONFIRMED
  (release-notes level).

## 6. dnf5 inside the Containerfile

- Version ground truth: F45 Beta shipped dnf5 5.4.3.0 (beta repo listing,
  notes/fedora-45-rebase.md §5); F44 currently ships 5.4.5.0; upstream
  latest is 5.4.6.0 (GitHub releases API, checked 2026-10-20,
  https://github.com/rpm-software-management/dnf5/releases). So the rebase
  moves dnf5 *backward* a minor — no new dnf5 behavior arrives in the
  Containerfile's `dnf -y install` steps with the rebase itself. CONFIRMED.
- The distro defaults do change around dnf5:
  - Repo definitions move to `/usr/share/dnf5/repos.d` (§3/§7). A
    Containerfile step that writes or deletes files under
    `/etc/yum.repos.d` now writes an override layer, not the packaged
    configs — which is actually the cleaner position (modified files stay
    in /etc and win outright; unmodified ones move to /usr; change page,
    Upgrade/compatibility impact). Any kuma Containerfile block that
    disables a Fedora repo by editing /etc/yum.repos.d/*.repo needs its
    path checked at rebase time. CONFIRMED mechanism; the audit of which
    kuma blocks touch that path is TODO (see checklist).
  - `allow_vendor_change = False` in F45's dnf5 defaults (FESCo #3643,
    https://forge.fedoraproject.org/fesco/tickets/issues/3643, via
    https://discussion.fedoraproject.org/t/f45-change-proposal-disable-vendor-change-by-default-system-wide/195269);
    the mesa-freeworld `--allowerasing` swap is an obsoletion, not a
    vendor switch, so it should be out of scope — verify on first 45 build
    (notes/fedora-45-rebase.md §5). BETA-STAGE.
  - rpm's `%_pkgverify_level=all` default (§5 above) — only the
    @commandline RPM Fusion URL install is exposed. UNVERIFIED at GA.

## 7. The rest of the Change Set, swept for a hardened bootc niri appliance

- Restrict ptrace by default
  (https://fedoraproject.org/wiki/Changes/Restrict_ptrace_by_default —
  CONFIRMED from the change page; FESCo #3569): F45 stops disabling Yama —
  `elfutils-libs` no longer Requires the `elfutils-default-yama-scope`
  sysctl override (renamed to `yama-ptrace-enable`), so a stock F45 system
  runs `kernel.yama.ptrace_scope = 1` (kernel default, attach-to-own-children
  only); installing a debugger Recommends the `yama-ptrace-enable` package,
  which restores `= 0`. This repo already pins
  `kernel.yama.ptrace_scope = 1` in its own hardening sysctls
  (src/containerfile/blocks.rs:3714-3716, src/containerfile/mod.rs:1024).
  Net effect: F45 makes kuma's hardening line the distro default — the
  doctor's grading of that check and any "deviation from stock" logic
  should expect `= 1` as the new normal, and kuma's explicit file now
  anchors `= 1` even when a debugger package pulls the enable override.
  No conflict either way; no code change needed, doctor expectations
  reviewed at rebase.
- Relocate RPM repository configs to /usr
  (https://fedoraproject.org/wiki/Changes/RelocateRpmRepoConfigsToUsr —
  CONFIRMED): covered in §3/§6. Note the change page still wears a
  "proposed" banner while the bot-generated Change Set lists it accepted
  (FESCo #3606) — the Change Set is the authoritative status page; the
  banner is stale. "Blocks release? Yes."
- Disable in Kernel Crypto Userspace API, Phase 1
  (https://fedoraproject.org/wiki/Changes/Disable_CRYPTO_USER_API —
  status "Finished" in the Change Set): no kernel-config delta appears in
  the branched f45 config — `CONFIG_CRYPTO_USER_API_{AEAD,HASH,RNG,SKCIPHER}=y`
  with `ENABLE_OBSOLETE` not set, identical in f44. Whatever phase 1 flips
  (the change text says restrict-to-active-users, deprecation first), it
  is not visible in the x86_64 fedora config as branched. Phase 1 of a
  removal; kuma ships no crypto-API user; monitor phase 2. CONFIRMED
  (config state) / UNVERIFIED (what phase 1 actually changed).
- Enable IPv6-mostly support in NetworkManager
  (https://fedoraproject.org/wiki/Changes/IPv6-Mostly_Support_In_NetworkManager):
  default-on IPv6-mostly networks. The appliance's networking is
  NetworkManager + firewalld; a behavior change in address-family
  preference on hostile networks is worth one first-boot look, nothing
  more. BETA-STAGE.
- Podman 6 (in at Beta as 6.1.0): slirp4netns and CNI removed upstream —
  pasta/netavark only. The hardening block's firewalld rule that lets the
  smoke's traffic arrive ("the zone's slirp rule" in AGENTS.md) names a
  lane podman 6 no longer populates by slirp4netns; the rule likely still
  matches pasta's interface naming, but this is exactly the kind of
  assumption the boot smoke verifies for free. Verify at first 45 boot
  (notes/fedora-45-rebase.md §4 covers the verb-level audit).
- SELinux policy: rpm-ostree 2026.3's /var/lib/selinux symlink fix (#5620)
  and the kmscon AVC report (§1) both say policy is churning around this
  release. No action; the smoke's clean-teardown reader is the detector.
- OpenSSL 4.0 rebase: listed in the Change Set with status "Not being
  worked on" — do not plan for it in 45. CONFIRMED (status field).
- What the Change Set does NOT contain: no sysctl/kargs changes beyond
  ptrace, no systemd unit renames touching the units kuma writes
  (greetd, niri, the shell), no firewalld default-shape changes. Swept
  the full page 2026-10-20.
