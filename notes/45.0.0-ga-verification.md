# Fedora 45 GA verification — post-GA re-check of the three research passes

Status: research written 2026-11-04, the day after F45 GA (announced 2026-11-03,
14:00 UTC — https://fedoramagazine.org/announcing-fedora-linux-45/, by Aoife
Moloney and Jef Spaleta). This file executes §8 "Re-verify after GA" of
notes/45.0.0-fedora-45-research.md and the "Stay lane" GA-era checks (items 3–4)
of notes/45.0.0-oo7-research.md, against primary sources only: the f45/f44
dist-git kernel configs, kojipkgs, the released F45 Everything repodata
(releases/45, compose dated 2026-10-31), the quay registry API,
gitlab.com/fedora/bootc/base-images, GitHub APIs for dnf5/image-builder, Bodhi,
and the GA announcement. Labels: CONFIRMED = verified from a primary source on
2026-11-04 unless noted; REPORTED = secondary source; UNVERIFIED = no source
found.

## Verdict

**Every load-bearing claim held. Nothing regressed. Two facts moved, both in
the "expect it" direction, and one lane has not flipped yet.** The f45 kernel
config is still byte-identical to f44 (re-diffed: zero lines); the GA kernel is
7.2.11-300.fc45 with 7.2.15 already stable in the updates lane; kmscon bumped
10.0.3→10.0.4 and stays installed by default; dnf5 at GA is 5.4.6.0 — newer
than F44's 5.4.5.0, closing the "rebase moves dnf5 backward" wrinkle; the dnf5
#2479 verify-level integration is closed and fixed upstream; image-builder is
at v89 with the bib_legacy path still maintained; and there are no post-GA
errata for greetd, gnome-keyring, dracut, or bootc beyond routine rides. The
one surprise: `fedora-45.yaml` in base-images still says `fedora-devel` — the
flip to the released repos has **not** landed at GA, so the :45 image is still
composed from the F45 composes via the REPOS_IMAGE lane (which now tracks the
release composes). Pin by digest and re-check the flip before regenerating
locks.

## 7. The unresolved items, chased as far as sources allow

### (a) dnf5 `--no-gpgchecks` × rpm's enforced `%_pkgverify_level` — FIXED upstream, CONFIRMED closed

- rpm-software-management/dnf5 issue #2479 was **closed 2025-12-04**
  (https://api.github.com/repos/rpm-software-management/dnf5/issues/2479).
  pmatilai's closing analysis: the verify-level integration "wasn't built at
  all" due to a cmake build-time detection bug in PR #2232; ppisar: "I will
  apply the patch there today" (to Fedora 44, 2025-12-04). So the fix has been
  in Fedora since F44 updates, and F45's 5.4.6.0 (2026 builds) carries it by
  construction. CONFIRMED (issue state + comments).
- What this means for the RPM Fusion release-RPM-by-URL install: the mechanism
  (cli switch properly lowering rpm's verify level for the @commandline
  package) is no longer a known-broken corner. The *behavior* of the specific
  non-interactive URL install under the enforced default remains a build-time
  test (rebase plan test 4) — no source can answer it without running dnf5.
  MECHANISM CONFIRMED / BEHAVIOR STILL TEST-ONLY.
